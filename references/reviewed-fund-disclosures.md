# 专用解析器未覆盖时：原文审阅到可计算披露

用于主动基金、QDII、债券和 FOF 的官方报告格式尚未由专用解析器验证时。分析者自行寻找最新官方报告、精确份额概要、招募说明书与重要业务通知，阅读决定判断的页码；这一步不需要用户填写 JSON 或挑子基金。

## 产品层

把核对后的精确份额来源写入运行目录的 `fund-document-sources` 注册文件，可通过 `research-fund <代码> --registry <该文件> --output-dir <新目录>` 调用现有原文采集与产品组装。格式见随 skill 提供的 `assets/fund-document-sources.json`；官方原文 URL、PDF SHA、原文页码、审阅事实和各字段的缺口分别保留。不要把运行期的新产品自动加入全局默认名单。

先取得和核对实际文件，再登记事实与 SHA；SHA 相同证明审阅所用版本未变，不能替代事实解释。家族说明书没有精确份额代码时，使用同次采集的精确份额概要和法律基金名称建立明确桥接。费用基数、赎回档、收费方式与日数不能从同一管理人的其他产品继承。当前费用解析器只验证其已登记布局；其他条款按原文计算并注明实际渠道折扣假设。

精确份额的交易/净值币种以该份额原文为准。家族持仓报告的记账币种属于持仓层，不能覆盖美元份额的币种合同；不要把报告的 `report_currency` 直接登记成所有份额的产品 `currency`。

## 持仓层

把已阅读的报告事实写入审阅文件，运行 `import-reviewed-fund-holdings <审阅JSON> --document-dir <原始PDF目录>`。原始 PDF 以 SHA 文件名保存。工具检查原文哈希、身份/日期/单位、引用的页码和原句、数值是否在原句中，以及金额与分母、显示精度能否对账。工具没有通用语义识别能力；分析者仍负责当前/比较列、页内上下文、口径和遗漏项。

审阅文件的核心结构：

```json
{
  "fund_code": "精确六位代码",
  "fund_family_name": "法律基金名称",
  "report_date": "YYYY-MM-DD",
  "publication_date": "YYYY-MM-DD",
  "publication_date_evidence": {"page": 1, "excerpt": "报告封面的送出/披露日期原句"},
  "report_currency": "CNY",
  "source": {"url": "官方原文HTTPS地址", "sha256": "实际PDF的SHA", "source_receipts": []},
  "identity_evidence": {"page": 5, "excerpt": "本基金身份表的精确代码原句"},
  "report_date_evidence": {"page": 1, "excerpt": "报告截止日期原句"},
  "unit_evidence": {"page": 17, "excerpt": "单位与报告币种原句"},
  "denominators": {
    "fund_net_assets": {"value": "原文金额", "evidence": {"page": 18, "excerpt": "当前净资产合计原句"}}
  },
  "securities": [],
  "allocations": []
}
```

每项证券含 `identity`、原文 `source_identifier`、`name`、`asset_class`、披露 `value` 或 `reported_percent`、`denominator`、`denominator_evidence` 与 `evidence`。百分比用原文的百分数，例如 8.5 表示 8.5%，不是 0.085。已知金额计算净资产占比；只有百分比时，需要其原文分母及分母金额。可用分母为 `fund_net_assets`、`total_assets`、`stock_assets`、`bond_assets`。未披露的百分比留空，不能把本地推算填成报告值。

配置表 `allocations` 另外含 `dimension`、`category` 和必要的 `classification_scheme`。维度包括资产类别、上市地区、行业、交易币种、资产负债表外汇敞口、明确披露的经济汇率敞口。上市地区与交易币种不能直接当作收入地区或完整经济汇率敞口。资产负债表外汇净额可以除以净资产得到有明确范围的风险比例，衍生品/对冲及企业收入暴露另查。

前三页或身份表较晚时，按报告自己的结构读取；当前接口要求 own-fund identity 在前五页，超过该布局时保留原文研究，不能移用其他页的代码冒充身份。万元、亿元等需要先形成显式单位转换依据；当前入口只接受原文基本货币单位，不能删单位直接输入放大后的数。

对已核对价格身份的股票/ETF，可补 `price_market`（CN/HK/US）及 `price_identity`。完整基金收集会自动继续研究最多四项主要已披露暴露的自身价格与曲线。排序以披露权重为依据，报告日期必须保留；这些是产品持仓，不是用户的私人仓位，也不是今天持仓的证明。其他地区/未匹配身份继续走原文和对应市场研究，不用指数代替证券价格。

原文送出/披露日期必须绑定封面或前部原句；中文日期可解析。来源目录日期与 PDF 送出日期不同则分别保留，当前入口的 `publication_date` 指绑定的 PDF 日期，不宣称已验证原始盘中可得时间。旧快照没有完成这个日期绑定时须重审原文后再导入，不能因存库时间较新而自动升级。

期货等合约用独立 `derivatives` 项记录 `identity`、`source_identifier`、带符号的 `signed_contracts`、`contract_value`、原句 `evidence` 与 `contract_value_evidence`。合约市值/名义金额、账面公允价值及变动值分别保留，不能相互替代。已知合约敞口另列，不加入股票或账面资产金额，不把异质合约汇总当成组合净风险；只核对若干合约也不宣称所有衍生品/对冲已审阅。

## 穿透与完整性

`fund-lookthrough` 和 `research-fund` 会读取该有来源的快照，并保留证券明细、分类覆盖和余项。十大明细不归一化成全仓。基金/ETF 子项在缺自己的报告时列为待穿透，不算完成 FOF/联接穿透；继续取得子层报告，按同一分母规则相乘，保留各层日期。复核后的现成联接解析器仍用于其已验证格式。

原文给出精确子份额代码时，在该基金/ETF证券项登记 `child_fund_code`，它必须与该项原文 `source_identifier` 中的六位代码一致。不能靠相似名字、同一基金家族或主基金代码替代持有份额身份。只有外国基金名称/ISIN或未匹配身份时先保留未知，主动查官方身份桥接，不填一个国内代码。

`fund-lookthrough-graph <根份额代码> --as-of <截止>` 只读展开已审阅子层。多条路径持有同一证券按精确价格身份合并；每层原文日期、币种与权重分母留在路径中。比例相乘不需要把各层原始金额强行换成同币种；同日数量与净值金额对账则必须有相应货币/汇率依据。子层缺报、循环或深度限制保留未展开权重，继续取得实质子层原文，不把缺口当零。

分类表按层保留，避免把父层已经穿透的行业表与子层行业再次相加。费用条款按层列出，实际合计需要核对各层计费基数与豁免；历史净值不再扣一次费用。期货审阅状态区别“原文确认无仓”和“没有审阅空表”，合约敞口独立列出。`all_referenced_children_resolved` 只说明已引用子层都取得，残余证券未披露时仍不是全持仓；所有标志都不证明今天的实际持仓。

账户限额公告的原文日期、上市/开放日、平台现时状态分别核对；目录列示日与 PDF 打印日不同则两者保留。外国底层曲线使用其来源的本地日历、币种和调整口径，不能套用国内复核日期。没有匹配收益口径和汇率的全球指数，不冒充已计算实际基金跟踪误差。
